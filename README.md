## 这一版的边界

- 保留红姐原版 30 题的题干、提示和术语；选项按用户确认的文案微调，不把整套问卷改成新手教学。
- 在上版 11 个补充选项基础上新增 20 项，修改第 1 题 C 和第 12 题 A / D；共 97 个选项。明确文案预期保存在 `tests/fixtures/approved-options.json`。
- 不设独立水平自评题，不问打过什么级别比赛或是否接近国家队。
- 从同一套场景选择推断人格与可能水平，两套映射分别计算。
- 复用原作全部 18 张人格 PNG（16 种常规人格 + IMFW / HUCK），网页、原图下载和导出报告都使用原图，不裁切、不重绘。
- 图片来源为上述原作提交的 `image/fbti/`，使用同名文件，原图字节保持不变。原版人格文案也随素材恢复。

## 微调选项

**文案在 `questions.json`，映射在 `scoring-map.json`。**

每道题和选项都有稳定 `id`，例如第 3 题原有 A 项为 `p03-a`，新增“呆住”为 `p03-extra1`。修改 `text` 或调整顺序时保留 ID。浏览器保存答案也使用 ID，改顺序不会把旧选择套到另一条选项。

改变意思时，需要重新评估该 ID 的人格权重、场景线索与彩蛋归属。新增 / 删除选项须同步增删映射；漏配会被测试和构建拒绝，不会默认为零分。用户确认的原题文案微调，应同步调整用于验证本次恢复的文案测试预期。

映射字段：

| 字段 | 含义 |
| --- | --- |
| `scores` | 原作 H/C、S/G、V/A、F/W 人格权重 |
| `ability` | 对盘权、空间、阅读、压力与配合的线索；空对象表示没有信息，不是低水平 |
| `reason` | 供维护者核对的映射依据，不在玩家报告展示 |
| `developing` | 这一场景明确依赖指令或尚未熟悉；用于多题交叉判断 |
| `egg` | IMFW / HUCK 彩蛋归属，独立于能力分 |
| `huckSupport` | 补充冒险决策线索，用于进一步收紧 HUCK 触发 |
| `rangeCeiling` | 对整个参考范围的上限约束；不会 Layout 为 6 |

## 评分说明

### 人格

原有选项沿用原作四维权重，初阶选项不强行归入某种人格。某维零分时显示“随场发挥”，同分显示“两边都有一点”；常规代码同分暂取左侧字母，内部规则不在报告解释。

至少 6 道 IMFW 线索且至少 5 个场景明确不熟练，才触发 IMFW；HUCK 则需要至少 3 道标志性线索、至少 3 道补充冒险决策，并且 G 权重占 S/G 总权重至少 65%，其余显示四维人格。HUCK 必须同时选择第 4 题个人强攻、第 9 题无视接应盲目 huck 和第 29 题抽盘笑话；补充冒险决策来自第 2、12、13、16 题的 B 项；正常下底接长传不算彩蛋线索。吃饭、休息等原版笑话不降低实力。“我是新手”、一次发懵和不会 Layout 都不直接触发彩蛋。

### 场景实力推断

只取有行为含义的线索，例如开场拉开空间、高 stall 找 Dump、切线冲突时清开、应对 Zone、主动 Reset、传盘后继续接应。喜欢赢、期待的技能、喜欢被怎样夸、外向程度、是否愿意 Layout、休息和加油均不直接加减技术分。

五类线索分别求平均后按权重合成：盘权处理 1.1、空间与接应 1.1、局势阅读 1.0、压力决策 1.2、配合执行 0.8。线索分描述该选择透露的意识，**不是实测技能分数**。

合成均值乘以 1.15。五类均有至少两道线索且均值不低于 5 时，增加 0.5 的交叉印证项，再四舍五入。明确初阶线索出现在至少 3 / 5 / 7 个不同场景时，中心预估分别不高于 L3 / L2 / L1，避免其他强制二选一题把初阶玩家抬成高手。场景线索与一致性保留用于内部校验，不在玩家报告展开。

没有线索的维度不按零分计入。有效场景不足 8 或覆盖维度不足 4 时，标记线索不足，中心最多 L4；完全无技术线索则暂用 L3±2，明确说明不能据此实测评级。

**仅凭这套场景题无法证明传接成功率、体能和比赛履历，因此中心预估最高 L7，参考区间最高到 L9。** 展示范围为 `[max(0, L−2), min(9, L+2)]`。例如多处初阶线索可能为 L1±2（L0–L3），成熟选择相互印证时可能为 L7±2（L5–L9）。L0–L9 是本站娱乐刻度，±2 不是统计置信区间；不会因为选了几个术语就认定为国家队水平。

用户指定的额外门槛：选择“我还不会 Layout”时，中心和区间上限均不超过 L6，区间变为 `[max(0, L−2), min(6, L+2)]`。例如其他选择较成熟时为 L6（L4–L6）；较初阶仍按原推断，不一律判低阶。会 Layout 但谨慎选择时机不受此限制。网页、分享文案和导出图共用同一范围；“±2”表示上下最多浮动 2 级，以具体区间为准。

玩家报告仅保留原版人格图、人格画像、等级范围、四维偏好和搭档。人格概览直接展示代码与名称，四张卡片按代码次序展示大字母、倾向含义和双方比例；导出图采用同样的字母卡片。已移除判断线索、Next Little Win、彩蛋映射与平局处理等内部说明；导出图同步精简。

## 本地开发与发布

Node.js 22+、Python 3，无 npm 运行依赖：

```sh
npm test
npm run build
python -m http.server 4175 --directory dist
```

打开 `http://localhost:4175/`。本地目录为 `D:\personal website\FBTI`。

`main` 推送后由 GitHub Actions 测试、构建和发布。`scripts/build.mjs` 只复制明确列出的公开资源及 18 张原图。不发布本地工具、登录记录或原版后端。

测试覆盖原题逐字恢复、原人格权重、18 张图片和搭档引用、偏好与能力分离、彩蛋门槛、回改答案、修改措辞与重排选项、一万种不同答案路径。`tests/fixtures/original-questions.json` 仅用作原作题目参考。

答案仅保存在当前浏览器，不上传服务器。新版使用 `fbti-v3.1` 缓存键，避免文案语义变化后把旧答案解释为新选择。图文全部本地生成，不依赖第三方截图服务。

发布时依据所有公开文本资源生成内容版本号，入口脚本、样式、模块导入和题库请求带相同版本参数，避免浏览器混用旧资源。存储格式与题目含义未变，因此保留 v3.1 答案，报告按新版规则重新计算。
