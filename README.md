# FBTI · 新人也能接住的版本

在线测试：**https://wch1007.github.io/FBTI-Revised-Version/**

在 [RED / 红姐的 FBTI](https://github.com/leishaforlinminzhi-9/FBTI) 基础上改编，改编者 wch1007。原始参考版本为 `b3ea5d40777c944d1450dbd4adbf9f3a9269ff08`。保留原作的 30 道场景框架、四维评分和 16 种常规人格，并改写题目、报告文案及交互。所有后续改动发布在本仓库，不修改原仓库。

## 新增内容

- 每道场景题都有新人能真实选择的答案，第三题包含“我就是那个懵的队友（呆住）”和“（乱跑）”。
- 飞盘术语改为日常语言，关键规则就地解释。
- 16 种常规人格 + IMFW（我是废物 · 萌新缓冲中）、HUCK（开大狂魔）、CHILL（草坪快乐居民）3 种彩蛋。
- 8 道实际能力自评，给出 L0–L9 中心预估和 ±2 浮动范围。
- 手机 / 桌面响应式布局、键盘答题、返回修改、本机保存进度、PNG 结果图和分享文案。
- 不依赖外部字体或脚本 CDN，不需要注册。答案只保存在当前浏览器，不上传服务器。托管服务可能保留常规访问日志。

## 评分说明

### 人格偏好

前 30 题沿用原作的四维加权：H/C（组织传盘 / 跑位接盘）、S/G（稳健 / 尝试）、V/A（沟通 / 执行）、F/W（快乐 / 竞技）。每题选项的 `scores` 独立累加。结果百分比是该维度的选项权重占比，不是正确率或技术水平。

不懂、没经历过等选项不强行贡献四维分数。某维没有分数时标记“有效线索不足”；有分但相等时标记“两边都有一点”。为了匹配原作结果，常规代码持平时暂用左侧字母，并在报告中说明。

彩蛋按以下优先级匹配，且不直接决定实力：

1. **IMFW**：选到至少 6 次 IMFW 选项，且占场景题至少 20%。这是自嘲人格，不评价人的价值。
2. **HUCK**：至少 2 次长传开大彩蛋选项。
3. **CHILL**：至少 3 次休息 / 场边支持 / 不飞扑的轻松选项。
4. 其他情况显示常规四字母人格。

### 实力预估

后 8 题必须按最近真实表现作答，各选项映射到 `0、2、4、6、8、9` 的自报线索分。没有参与过就选第一项。

| 自评项目 | 权重 |
| --- | ---: |
| 传盘基本功 | 1.3 |
| 接盘稳定度 | 1.2 |
| 跑位与空间 | 1.0 |
| 防守与阅读 | 1.0 |
| 规则与配合 | 0.8 |
| 实战经历 | 1.3 |
| 比赛续航 | 1.0 |
| 压力下的稳定 | 1.4 |

先计算加权平均。前 30 题中明确表示不熟悉场景的比例乘以 3，作为最多 1.5 级的下调，再四舍五入。避免把自信当技术：最高预估不超过“实战经历选项分 +1”；实战经历没有选最高档时，不给 L9。选择不飞扑、休息、场边支持和偏好求稳均不触发熟悉度下调。

参考范围为 `[max(0, L−2), min(9, L+2)]`。例如 L0 显示 L0–L2，L9 显示 L7–L9。八项分数最大差值达到 6，或大量陌生场景答案与高技能自评矛盾时，报告提示线索有反差。

L0 初来乍到、L1 萌新上场、L2 入门盘友、L3 草坪熟面孔、L4 靠谱队友、L5 进阶选手、L6 比赛常客、L7 高阶战力、L8 全国强队级、L9 国家队级。

**这是本站自定义的娱乐估计，没有校准数据。±2 不是统计置信区间，也不是官方分级、心理测评、技术认证或国家队选拔依据。** 人格报告中的优势是风格画像，不是实测能力。改变性格偏好不会自动提升实力；想拥有的技能也不给实力加分。

## 本地开发

Node.js 22+ 和 Python 3：

```sh
npm test
npm run build
python -m http.server 4175 --directory dist
```

打开 `http://localhost:4175/`。没有 npm 运行依赖。不要直接双击 HTML：浏览器对本地文件的 JSON 请求有限制。

- `questions.json`：题目、人格权重、彩蛋和能力证据。
- `results.json`：人格文案与搭档。
- `scoring.js`：独立可测试的计分系统。
- `app.js` / `styles.css`：页面与交互。
- `report.js`：浏览器本地生成 PNG 分享卡。
- `tests/scoring.test.js`：边界、彩蛋、分离计分、回改和随机路径验证。
- `standalone.html`：兼容原链接，跳转至新版入口。

## 发布

`main` 分支推送后，GitHub Actions 先测试和构建，再部署到 GitHub Pages。Pages 的部署来源设为 **GitHub Actions**。构建只复制明确列出的公开站点文件；不发布脚本、测试、本地状态或任何原作登录数据。

原版后端和登录记录未引入。本地工作目录为 `D:\personal website\FBTI`。浏览器缓存使用 `fbti-v2.0` 版本键；修改题目结构或选项顺序时应同时递增 `scoring.js` 中的 `VERSION`，避免旧答案对到新选项。
